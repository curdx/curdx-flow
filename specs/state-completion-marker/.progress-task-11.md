## Learnings
- Shared `CurdxState` in `_shared/types.ts` is a strict superset of the inline one previously in update-spec-index.ts (phase/taskIndex/totalTasks/awaitingApproval) and adds the new v7.1.0 fields `completed` / `completedAt`. No field loss when dropping inline copy.
- Verify pipeline uses literal-string grep `import type { CurdxState }` (with closing brace), so combining `CurdxState` and `HookOutput as _HookOutputRef` into a single `import type {...}` line FAILS the verify. Solution: keep them as two separate `import type` lines from the same module — esbuild dedupes at bundle time, zero runtime cost.
- Short-circuit ordering matters: `state.completed === true` MUST be checked FIRST inside `if (state) {}`, before the `state.phase ?? "unknown"` path, otherwise a stale `phase: "execution"` left over by a writer that didn't clear `phase` would leak into the index even after `completed` flipped to true. Used strict `=== true` (not truthiness) per shared CurdxState contract — matches NFR-2 backwards-compat for v7.0.x states without the `completed` field.
- Task counters (`taskIndex`/`totalTasks`) are only emitted in the completed branch when `totalTasks > 0`, mirroring the existing pattern that avoids fabricating `0/0 tasks`.
- `inferPhaseFromFiles` already had its own "completed" branch (tasks.md fully checked OR .progress.md present), so the new state-based short-circuit is purely additive: it lets specs whose tasks.md is in non-standard form still surface `completed` from the marker, no longer relying on `.progress.md` heuristics.
