## Learnings

- **Biggest open Q**: events.jsonl unified vs errors.jsonl split — 影响 OB-3 join 模式，design 必须先决议
- **Cross-platform 是 NFR 非 nice-to-have**: Windows EBUSY/EPERM + EXDEV 都要 mitigation，CI matrix 4-leg 是验收门
- **Rotation throttle N=10 是性能 critical path**: 每次 statSync = ~1ms，30 call/spec p99 budget 50ms 不能浪费
- **correlationId helper 必须在 _shared/correlation.ts**: 4 hook 各自拼会漂移；helper 强制 source 一致
- **Round-trip 是 binary acceptance**: AC-3.1 + AC-11.1（4 测试 0 改动）是同一个意思的两面，违反任一即破
- **33 site 数字必须 match research 映射**: 漏改 site → grep `logError(` baseline 比对，CI 应加 site count check（risk R4）
- **10 kind 枚举 zero dead member**: research 已验证全 hook 实际触发覆盖，design 不能扩展、实施不能漏
- **Payload redact white-list 是 deferred design Q**: requirements 留空、design 决议；不能 v1 收口
- **D1 决议 UNIFIED**: 文件名保留 `errors.jsonl` 向后兼容，语义升级为 events 流；rename 是 v2 work
- **D2 决议 hardcoded retention=5**: YAGNI；配置化是 v2 settings.json schema PR
- **D3 决议 suffix `<ISO-ts>-<pid>`**: 时间字典序 = sort 顺序，pid 是 defense-in-depth 而非常规需要
- **D4 决议复用 redact.ts D-9 white-list**: 单一 source-of-truth；新字段名走 redact.ts 升级 PR
- **logHookError 转发模式**: 老 API 不变签名，内部委托 logHookEvent({level:'error', kind:'unknown'})，AC9 round-trip 自动
- **safeRename 3 阶 fallback ≤30 LOC**: rename → EBUSY retry 50/200/500ms → EXDEV copy+unlink；全 swallow（NFR-9）
- **Site 数字 33 是下限**: 设计估算 34 留 1 缓冲；CI grep count check 是 R4 mitigation
- **rotateIfNeeded throttle 9/10 跳过 statSync**: 是 p99 50ms budget 关键，不可省

## Learnings
- `logHookError` 的 redirect 写法要求 `LogHookErrorContext` 增加 `kind?: EventKind` 字段，否则 `ctx.kind ?? 'unknown'` 不通过 TS — 这是纯加性变更，不破坏 4 现有 case
- `logHookEvent` 默认 `level='info'` `kind='unknown'`；`logHookError` redirect 时显式覆写 `level='error'`，保持现有 4 case 中 `level: 'error'` 断言通过
- 4KB 行 cap cascade 多加一层 `delete record.payload`（payload 是最大潜在 overflow 源，但价值最高所以最后丢）
- `coerceKind` 只接受 `KNOWN_KINDS` Set 内字符串，其余（含 undefined / 非 string / 未来版本 kind）一律 → `'unknown'`，AC1 round-trip 自动
- `safeRename` 只用 16 LOC（远低于 30 上限）：内层 try `renameSync` → EBUSY/EPERM 三阶 retry（busy-wait spin，因为 hook 内不可 await）→ EXDEV/exhausted 走 `copyFileSync + unlinkSync` → 外层兜底 catch
- `rotateIfNeeded` throttle 用 module-level `let rotateCounter = 0; rotateCounter = (rotateCounter + 1) % 10`，仅 `counter === 0` 时才 statSync — 把 stat 成本摊薄 10× 进 p99 50ms 预算
- `pruneRotatedFiles` glob 必须显式排除 `errors.jsonl` (live) — 仅 `name.startsWith('errors.') && name.endsWith('.jsonl') && name !== 'errors.jsonl'` 才算 rotated
- ISO-ts suffix 用 `replace(/[-:]/g,'').replace(/\.\d+/,'')` 把 `2026-05-07T12:00:00.000Z` 压成 `20260507T120000Z` — 字典序 = 时间序，pid 后缀防同秒撞名
- 整合点：`mkdirSync` → `rotateIfNeeded(ERRORS_LOG)` → `appendFileSync` (rotation 必须在 append 前做才能命中"先 rename 再起新文件"的语义)
- 测试 mock 的 `node:fs` 只 stub 3 个方法，新增 `statSync/renameSync/readdirSync/copyFileSync/unlinkSync` 都靠 NEVER-throw 兜底自动 silent — 现有 4 case 0 改动 (AC9 自动)
