### Release 代价

### 依赖策略（重要架构决策）
**允许 npm deps + 用 esbuild bundle 成单文件 .mjs**。意味着：
- 源码可能放 `src/hooks/<name>.ts`

### Learnings (Phase 1.19 hooks.json switch to node + .mjs + shell:bash + async)
- **3 of 3 hook events flipped** (SessionStart / PreToolUse / Stop). update-spec-index intentionally omitted — it's a CLI invoked by /curdx-flow commands, not a Claude Code hook event.
- **Before/after diff** (per hook entry): `${CLAUDE_PLUGIN_ROOT}/hooks/scripts/<name>.sh` → `node "${CLAUDE_PLUGIN_ROOT}/hooks/scripts/<name>.mjs"`. The literal embedded `"` around the path is escaped as `\"` in the JSON string so paths-with-spaces (Windows `C:\Users\First Last\...`) survive bash word-splitting after `${CLAUDE_PLUGIN_ROOT}` expansion.
- **`"shell": "bash"` on all 3 entries** — Claude Code's cross-platform bridge. On Windows this routes via Git Bash on PATH (Claude Code default), so `node "..."` parses uniformly across all OSes regardless of native shell.
- **`"async": true` ONLY on SessionStart** — mitigates Issue #34457 (sync session-start hooks block UI startup). Not needed on PreToolUse / Stop (their semantics rely on synchronous gating + completion signals).
- **`"timeout": 10` preserved on PreToolUse/quick-mode-guard** — caps slow guard at 10s so a stuck hook doesn't stall the AskUserQuestion path.
- **Verify gate quirk**: original `grep -c 'node "'` doesn't match because in the JSON file the byte sequence after `node` is `\"` (escaped backslash-quote), not bare `"`. Used semantic verification instead — Node parses the JSON and asserts: 3 command entries / 3 node+.mjs / 3 shell:bash / 1 async:true on SessionStart / timeout:10 preserved. All green.
- **Old `.sh` files NOT deleted** — task 4.7 handles that (separate commit so revert is one-click if Windows runner reports issues during alpha.0).
- **JSON parses cleanly**: `node -e "JSON.parse(require('fs').readFileSync(...))"` exit 0; pretty-print round-trip identical to source.

- **stat-mtime unit conversion (Risk R8 audit point)**: `stat -f %m` / `stat -c %Y` return seconds; `fs.statSync(p).mtimeMs` returns milliseconds. Two call sites: (a) state-file race-window check — original was `(now-mtime) < 2 sec`; we compare `Date.now() - mtimeMs < 2000` (ms-vs-ms). (b) cleanup of stale `.progress-task-*.md` files — original was `find -mmin +60` (>60 min); we compare `Date.now() - mtimeMs > 60*60*1000`. Both unit-correct.
- **`./` prefix preservation**: same issue as 1.14 (path-resolver's `posix.join` strips `./` from serialized paths but bash kept it via plain string concat). Fixed locally with `preserveDotPrefix()` helper rather than upstream in path-resolver — keeps the shared module unchanged for other callers (quick-mode-guard, load-spec-context don't need it).
- **jq's `// true` default-trigger quirk on `nativeSyncEnabled`**: jq's `//` operator treats BOTH `null` AND `false` as default-triggers, so `.nativeSyncEnabled // true` always returns `true` whenever the field is null/missing/false. Documented inline + mirrored in `jqDefaultTrue()`. The state schema constrains the field to bool/missing so the helper effectively always returns true; preserved verbatim for byte-equal continuation prompts.
- **Bash command-substitution strips trailing newlines**: `PARALLEL_TASKS=$(awk ...)` drops the trailing `\n` that the awk's `block=block $0 "\n"` accumulator produces. Mirrored with `block.replace(/\n+$/, "")` in `extractParallelGroupBlock`. Critical for the heredoc layout to render with the right blank-line count between TASK_BLOCK and the PARALLEL_INSTRUCTIONS line.
- **ALL_TASKS_COMPLETE regex parity**: `/(^|\W)ALL_TASKS_COMPLETE(\W|$)/` matches grep's `(^|\W)ALL_TASKS_COMPLETE(\W|$)` — JS `\W` is `[^A-Za-z0-9_]` which is identical to POSIX `[^[:alnum:]_]` for ASCII transcript text. Detection verified on synthetic transcript fixture; both bash and node print the same `[curdx-flow] ALL_TASKS_COMPLETE detected in transcript` stderr line and exit 0 silently on stdout.
- **Update-spec-index spawn**: replaces `"$SCRIPT_DIR/update-spec-index.sh" --quiet` with detached `child.spawn(process.execPath, [bundledMjs, "--quiet"], {stdio:"ignore", detached:true}); child.unref();` — fire-and-forget, never blocks the stop-hook return.
- **Output contract**: silent exit 0 on all "no-block" paths (matches v6 silent exit). JSON `{decision:"block",reason,systemMessage}` only on the four block paths: corrupt state, quick-mode-active-non-execution, unchecked-tasks-but-state-says-complete, and continuation. Each emit has trailing `\n` per v6 jq output convention.

### Learnings (Phase 1.16 markdown-task-parser)
- **Files**: `src/hooks/_shared/markdown-task-parser.ts` (230 LOC, 3 named exports — `extractTaskBlock`, `parseTaskList`, `TaskMeta` type)

- **Awk count-frozen quirk preserved verbatim**: stop-watcher.sh's awk increments `count` only when `count != idx`. Once `count == idx` fires, count stays frozen, so the block sweeps through the target task PLUS every subsequent sibling task until a non-task heading or EOF closes it. This is awk's actual behavior on the existing input format and stop-watcher's coordinator prompt already tolerates it (first task line = "current"; trailing tasks = extra context). Documented inline as a "do NOT fix without coordinated change" warning so 1.17 doesn't try to clean it up unilaterally.
- **Block close conditions** (mirrors awk arms): (a) any non-empty, non-indented line that isn't a task line (heading/prose); (b) EOF. Indented lines (≥2 spaces) and blank lines belong to the current block; trailing blanks stripped to match the `sed -e :a -e '/^[[:space:]]*$/{ ... }'` post-filter.
