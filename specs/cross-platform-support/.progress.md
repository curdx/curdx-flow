## Interview Responses

### 目标平台
**Windows + macOS + Linux 三平台**（含 Windows WSL/Git Bash/PowerShell）。理由：彻底解决，避免后续补丁。

### 重写策略
**Node .mjs 全替换 .sh，并消除 markdown 里所有 jq 命令**。hooks.json 改为 `command: node ${CLAUDE_PLUGIN_ROOT}/hooks/scripts/<name>.mjs`。Node 18+（Claude Code 已依赖）。

### 处理边界
**全量打透**：hooks/scripts/*.sh + 所有 markdown 里的 bash/jq 命令 + templates。验收 gate：`grep -rn '\bjq\b' plugins/curdx-flow` 必须为空。

### Release 代价
**Major bump 到 v7.0.0**。CHANGELOG 显式列 BREAKING CHANGE：jq 不再是依赖；hooks.json 命令格式改变。

### 依赖策略（重要架构决策）
**允许 npm deps + 用 esbuild bundle 成单文件 .mjs**。意味着：
- 源码可能放 `src/hooks/<name>.ts`
- 加 build step 产出 `plugins/curdx-flow/hooks/scripts/<name>.mjs`（单文件、零运行时依赖）
- npm script 加进 prepublishOnly 链
- Design 阶段需决定：bundled .mjs 是 commit 还是 .gitignore？（与 src→dist 类似但 plugin 资产必须随 npm publish 走）

### Markdown 里 jq/bash 处理
**优先 Node one-liner（node -e '...'）；复杂的提取为 `hooks/scripts/lib/` 共享小脚本**。保留 prompt 可执行性，避免依赖模型推理重新生成命令。

### 验收标准
**GitHub Actions 三矩阵 CI**：windows-latest / macos-latest / ubuntu-latest 跑全部 hook smoke test（每个 hook 喂 stdin JSON、断言 exit code）。release.yml 之前必须绿。

## Learnings (Requirements Phase)
- **NFR-7 byte-equal 等价**：Linux+macOS 与 v6 必须 byte-equal，但要显式排除 path separator 与 mtime 字段——这两点跨平台必然不同；如果未来发现还有其他差异源，需要在 design 阶段追加排除清单
- **lib/ 工具清单留给 design**：45 处 extract-to-lib 的归并（哪些合并成同一 lib 工具）不在 requirements 决策，避免 over-spec；design 阶段需用 jobs-to-be-done 视角重新归并
- **smoke test runner 留给 design**：vitest vs bats 是 design tradeoff（toolchain 一致性 vs 真实 spawn 语义），requirements 只声明"必须有 smoke test"
- **release.yml 三矩阵依赖留给 design**：实现路径未定（`workflow_run` 触发 / release.yml 内复用同矩阵 / 手动 gate），requirements 只声明 outcome
- **Issue #267 fallback 留给 design**：`.mjs` vs `.cjs` 选型取决于 Windows runner 上的实测；requirements 假设 `.mjs` + colocated `package.json {"type":"module"}` 能解决，但允许 design 阶段降级
- **删除旧 .sh 是 BREAKING**：FR-18 标记 Medium 但放进 BREAKING CHANGE 列表（v7.0.0 入口）；老用户若 fork 了原 .sh 路径会断
- **stop-watcher OS-specific stat**：`stat -f %m` (macOS) vs `stat -c %Y` (Linux) 的 OS 分支由 Node `fs.statSync(path).mtimeMs` 统一；这是 v6 → v7 的隐式行为变化（mtime 精度 sec → ms），但允许在 byte-equal 排除清单内
- **SessionStart `async: true` 是 mitigation 不是优化**：性能 NFR-1 < 200ms 是 P95 目标但不依赖 async；async 是为了避开 Windows event-loop 死锁（GH #34457），即使 P95 < 200ms 仍必须保留 async 标志
- **hooks/scripts/package.json {"type":"module"}** 是 mitigation for #267（Windows nvm + npm.cmd 把 .mjs 误派给 CJS loader）；不是必要的 ESM 声明
- **Markdown sweep 14/45/20 分类来自 research**：14 node-oneliner / 45 extract-to-lib / 20 inline-prose，加总 79 与 research catalog 完全匹配；requirements 直接锁定这三个数

## Learnings (Design Phase)
- **CLAUDE.md 矛盾**："plugin shipped as static files — no build step" 与 v7 引入 esbuild pipeline 直接冲突；File Plan 必须含 `modify CLAUDE.md` 一项，release SOP 也要同步更新
- **Lib 工具 catalog 11 个**：merge-state、count-tasks、cleanup-files、ensure-gitignore、search-files、count-mocks、get-default-branch、kill-port、update-modification-map、update-fix-task-map、init-execution-state；tasks 阶段可能压缩到 9-10（`get-fix-attempts`/`mark-task-complete` 合并候选）
- **release.yml 选 workflow_run 而非 needs:ci**：tag push 触发 release.yml 时 CI 是平行触发的，`needs:` 只能链同 workflow 内 jobs；workflow_run 等 CI 完成后读 conclusion，代价是延迟 ~15 分钟
- **CI 矩阵优化为 6 leg 而非 9 leg**：Linux 跑 Node 20+22；macOS+Windows 各只跑 Node 22；外加 typecheck + check-fresh 两个 ubuntu-only job + 一个 all-green 聚合 job
- **path.posix 用于 state file 内的路径序列化**：跨平台 stable，避免 `\\` 转义地狱；fs IO 仍用 path.join（平台原生分隔符）
- **错误路径全部 exit 0 不阻塞会话**：hook crash → stderr log + exit 0；exit 1 会阻断 Claude Code 工作流
- **stop-watcher TDD 风险**：awk → regex 状态机翻译是最大单点风险（362 LOC + 复杂状态机），强烈建议先写 fixture + 期望反推 regex
- **byte-equal baseline 应手动生成 commit 进仓**：checkout v6.0.6 tag 跑 .sh 存 baseline snapshot；baseline 永不变，无需 git LFS
- **alpha.0 应早 bump 让 CI 先跑通**：先 bump 7.0.0-alpha.0 git tag 让三平台 CI 验证 esbuild + #267 + Windows 实测，再追加修复 commit；不要等所有 task 完才 bump
