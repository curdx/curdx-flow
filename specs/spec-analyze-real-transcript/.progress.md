## Learnings

- Epic 写 4 个 fixturePath site 是错的，实测 5 处（L112 单独 resolve 调用被遗漏）— 任何后续实施必须按 5 处替换
- Multi-session 是常态非边角（实测 66 个 .jsonl）— dedup 必须严格，复用 filter.ts `uuid|requestId` 复合 key
- State file 按 path key 存储是 multi-session 累积 orphan 的根因 — GC 是必须，非锦上添花
- Open Question Q1（exit code ≠ 0 vs 0）是设计阶段最大冲突 — epic AC3 与 ccusage UX 直接对立，需用户/design 决议
- `--session` × `--since` 组合可能产生空集 — 应作 friendly 提示而非 error（R5 风险）
- realpath 时机若放在每次 path resolve 都做会有 syscall 开销 — cache 在 cwd 入参时一次性解析（Q3 推荐）
- D2 双阈值（mtime OR keys）优于单阈值：单 mtime 误伤多短命项目用户，单 keys 误伤长寿单项目用户 — 取 whichever-first 容错最广
- D4 1-level glob 是 ccusage 黄金参考已验证模式；YAGNI 优于显式 blacklist 维护
- TranscriptNotFoundError 单独 error class + index.ts 顶层 catch → 既保 friendly 2-line 输出又不污染其他 stack trace
- realpath 物理路径 ≠ user cwd 时 state key 用 realpath 但 error 显示原 cwd —— 双显示避免用户路径困惑（设计阶段新发现的 risk）
- Task planning: 9 tasks total (S-size cap respected); 2.1 + 2.2 marked [P] (zero file overlap: transcript-path.ts vs index.ts GC helper)
- Test command is `npm run test:analyze` (vitest run tests/analyze), NOT `npm test`; full suite is `npm run verify`
- Integration test edit is minimal (beforeAll/afterAll env var only) — no snapshot changes needed; this was the POC compatibility gate in task 1.3
- State GC tests can live in transcript-path.test.ts (same file as resolver tests) — avoids proliferating test files for S-size spec
- Task 1.1: `readdirSync(... { withFileTypes: true })` overload returns `Dirent<NonSharedBuffer>[]` under strict TS — must explicitly type as `Dirent[]` (string variant) to avoid buffer-overload pickup; using `ReturnType<typeof readdirSync>` defaults wrong way
- Task 1.1: design.md Component 1 API has richer real-variant fields (`realCwd`, `encodedDir`) than the task body's minimal trio — honored design (downstream Task 1.2 needs them for state-key + error display)
- Task 1.2: CLI `--session` flag lives in `src/flows/analyze.ts` (citty defineCommand), not `src/analyze/index.ts` — index.ts only owns programmatic API; flow file is the layer that surfaces `args.session` to runAnalyze
- Task 1.2: Multi-path rotation check became per-file (each `.jsonl` has independent size/mtime); idempotent-replay short-circuit now requires ALL paths to be cached-ready (`allCachedReady` aggregate flag) — single rotated file invalidates the cache
- Task 1.2: Added `session?: string` to Options interface in types.ts to keep cross-module type contract stable; AnalyzeOptions in flows/analyze.ts mirrors it
- Task 1.2: Refactored runAnalyze into runAnalyzeInner (pure logic) + thin runAnalyze wrapper that catches TranscriptNotFoundError → friendly 2-line stderr + exit 1 (D1/AC3); other errors propagate so unit tests still see real stack traces
- Task 1.2 verify: NFR-1 timing integration test fails when env var points to fixed `tests/analyze/fixtures/sample.jsonl` because that test stages an inflated fixture under tmpdir and asserts state key matches inflated path — Task 1.3's `beforeAll` env-var-to-inflated-path wiring is the explicit fix; this is by design
- Task 1.3: actual failure surface was 2 tests (NFR-1 timing AND fixture snapshot), not 1 — the snapshot test also calls runAnalyze in real cwd which has no `~/.claude/projects/-Users-wdx-opc-curdx-flow/` dir on the runner. Suite-level `beforeAll` covers snapshot; test-level override covers timing. Same diff path, two failure sites resolved in one patch.
- Task 1.3: cwdSpy in NFR-1 test became redundant once env var bypasses cwd-based glob, but kept to minimize surgery (constraint: "patch the 1 failing one, don't restructure")
- Task 1.3: env var save-and-restore via local var is required because NFR-1 test override would otherwise leak past its scope — `delete + reassign` only works when prior value is `undefined`
- Task 2.1: `opts.homedir` already exposed by resolver design — no need to mock `os.homedir()` or set `HOME=`; per-test `mkdtempSync(os.tmpdir(), 'curdx-resolver-')` + injection is fully cross-platform and avoids env-leak between tests
- Task 2.1: Module-level REALPATH_CACHE could in theory carry between tests, but since each test uses unique synthetic cwds (`/Users/x/foo`, `/Users/x/multi.session-test`, etc.) and cwds in cache hash by string, no cross-pollution possible
- Task 2.1: Honored task 2.1 spec exactly (5 cases as listed) including the "encoding edge cases" implicit via `multi.session-test` cwd which exercises both `.` and `-` chars in the encoded basename
- Task 2.1: 33/33 tests now pass (28 baseline + 5 new); zero existing test churn
