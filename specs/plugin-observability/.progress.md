# plugin-observability — execution journal

## Goal

为 curdx-flow 插件构建自我观测能力，让 plugin owner 能基于真实使用数据反向优化插件设计。

**范围（用户已对齐, 5/5 turns）**：

- **方案 3（解析器为主 + 错误埋点为辅）**
  - 主体：解析 `~/.claude/projects/<工程目录>/<sessionId>.jsonl` 现有 transcript，提取与 curdx-flow 相关的事件（hook 触发、tool call、subagent 调度、slash command 使用）。
  - 辅助：在 4 个 hook 脚本（`load-spec-context`, `quick-mode-guard`, `stop-watcher`, `update-spec-index`）的错误路径加埋点，写入 `~/.claude/curdx-flow/errors.jsonl`。
- **数据落地**：本地 only，不上报。
- **消费形态**：`npx @curdx/flow analyze` CLI 子命令，输出 markdown 报告。
- **不在范围内**：web dashboard、上报通道、实时流处理。

**未来扩展挂载点（不在本期实现）**：
- 用户自愿上报通道
- 本地 web dashboard
- 跨用户对比分析

## Learnings (requirements phase)

- **AC-9.1 揭示 settings 读取时序问题**：errors.jsonl 写入发生在 hook 中央 catch，需在 `_shared/run-hook.ts` 启动时读 settings.json 缓存 `errorLogEnabled`，避免每次 hook 触发都同步读盘（可能拖慢 quick-mode-guard）→ 留给 design 处理。
- **FR-18 `--project` 默认行为未定**（OQ-2）：影响 US-1..6 全部 story 的"开箱即用"体验；建议 design 阶段倾向 cwd 推断 + 不存在则全量。
- **FR-7 全量 7 报告 MVP 工作量评估偏乐观**：5 核心 + 2 漂移虽然数据源都现成，但 fixture jsonl 需要构造 7 类事件覆盖（含 v2.1.126 attribution + v2.1.119 旧字段 fallback），实际 fixture 维护成本可能超出 research 估算的 S–M。
- **隐私边界（FR-13）与漂移诊断（AC-6.1）冲突点**：parentUuid 断链率需要遍历完整 uuid 链，但 redact-by-default 不能输出原 uuid → design 需明确 uuid hash 策略（仅输出统计百分比，不输出具体 uuid 列表）。
- **NFR-3 bundle 增量 20KB 是软目标**：含 7 类报告渲染 + schema map 加载 + redact util，design 时若超标先考虑 lazy-load `analyze` 子命令而非砍功能。
- **AC-1.2 双源合并的去重风险**：jsonl `hook_success.exitCode≠0` 与 errors.jsonl 可能记录同一次失败（hook 主流程错 + 中央 catch 写日志）→ 需要 design 明确 join key（toolUseID + ts 窗口？）。
- **观察**：所有 AT 都基于 fixture jsonl，无真实 session 录制。建议 implement 阶段额外用本机 `~/.claude/projects/` 真实文件做冒烟（reality verification）。

## Learnings (design phase)

- **HookStdin 仅 3 字段（cwd/transcript_path/stop_hook_active）**：errors.jsonl 无法直接拿到 sessionId/toolUseID（types.ts:46-50 验证）。AC-1.2 双源 join 退化为 `(hook, ts ±2s, cwd)` 模糊匹配；implement 阶段需评估精度是否够用，不够则需 Claude Code 上游加字段。
- **offset 失效检测降级为 size 倒退**（D-1）：放弃 inode/SHA-256，按 KISS 原则只看 `size < lastSize || mtime < lastMtime` 视为 rotate 全量重读；jsonl 是 append-only 设计，rotate 极少但需在 README 提示。
- **D-3 requestId 缺失 fallback 是隐性兼容性炸弹**：v2.1.119 旧事件无 requestId，与 v2.1.126+ 共存时不能整段丢；fallback 退化为 uuid 单键去重——如果用户混用新旧 session 文件可能漏算 retry，影响 NFR-1 报告精度但保证不挂。
- **redact 走"白名单透出"模式（D-9 配套）**：默认全裁，显式列出可输出字段，新增 schema 字段默认被 redact；implement 时需在 redact.ts 加测试守护，避免 schema map 加 type 时忘改 redact 漏数据。
- **bundle 增量 20KB 是 CI gate 而非软目标**：D-5 lazy import 改造作为 NFR-3 超阈的兜底；implement 时第一版不要预判 lazy，先跑 `wc -c` 实测，超阈才动。
- **--project cwd 推断在非 git 仓库会失败**：R-10 兜底为 exit 0 + warning + 空报告；如果用户在 `~/Desktop` 跑会拿到空报告而非错误，UX 需要清晰的 warning 文案。
- **schema map JSON 与 plugin.json 同分发**（OQ-1 解决）：放 `plugins/curdx-flow/schemas/transcript-events.json`，但 src/analyze/parser.ts 是 npm CLI 的代码，跨包读取需要 `__dirname` 相对路径解析——implement 时确认 tsup bundle 后路径可解（fallback 内置最小白名单已设计为安全网）。

## Learnings (implement phase)

- **Project uses `.ts` import suffixes, not `.js`** — `tsconfig.json` sets `allowImportingTsExtensions: true` and `verbatimModuleSyntax: true`. Existing imports in `src/index.ts` (`./flows/status.ts`, `./i18n/index.ts`) all use `.ts`. Followed that convention for `./flows/analyze.ts` even though task spec said `.js`. Build green, typecheck green.
- **citty `--limit` typed as `string`** — `type: 'number'` is not a citty arg type; coerced inside `run()` via `Number(args.limit)`.
- **`node dist/index.mjs --help` shows interactive menu, not help** — pre-existing dispatcher behavior in `src/index.ts:158`: `firstNonFlag` skips all `-`-prefixed args, so `--help` falls through to the menu branch. Not introduced by Task 1.1; flagged for potential future polish.
