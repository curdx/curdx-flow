## Learnings (Task 2.5, 2026-05-07)

- **parseCorrelationId 严格 3 段判定**：`split(':')` length !== 3 或任一段空字符串 → 整体回 `{}` 而不是部分匹配。部分匹配会让 `parsed.sid` 出现而 `parsed.task` 缺，导致 spec 维度桶命中但 task 维度走 unknown，跨 level 总和不一致（双计风险）。Decision 11 双分桶能成立的前提就是 correlationId 全段一致或全段缺。

## Learnings (Task 4.6, 2026-05-07)

- **renderReport 单 pass 接 costBreakdown + recommendations**：原 Phase 1 POC 用 `markdownStr = ${markdown}\n## Cost Summary\n...` 字符串拼接（双 render 路径），4.6 改为在调用 `renderReport` 之前算好 `costBreakdown` + `recommendations`，作为 `RenderOptions` 一次性传入（report.ts 4.4/4.5 已就位）。这干掉了 Phase 1 POC 留下的 `## Cost Summary` 旧标题，markdown 现在统一为 `## Cost Breakdown` (R1-R7) + `## Recommendations`（Decision 4 紧跟其后）
- **顺序很关键 — recommend() 必须在 renderReport 之前算**：renderReport 接 `recommendations: Recommendation[]` 作为 RenderOptions 字段，而 `recommend()` 的入参是 `aggregateBy` 的输出 buckets。所以 cost branch 重排为：`extractUsage → aggregateBy → recommend → renderReport`，比原来的 `renderReport → 字符串拼接` 路径更线性
- **allBuckets 合并三 level 喂 recommend**：每条 rule 在 dispatch 时按 `b.level !== 'task'` 等过滤无效 scope，所以 caller 把 spec/phase/task 三个 array 简单 concat 成 `allBuckets` 即可，不需要 caller 知道每 rule 的 scope 偏好。这与 recommend.ts 的 dispatch 设计契合（per-rule scope filter 在 rule body 内）
- **conditional spread `...(costBreakdown ? { costBreakdown } : {})`**：RenderOptions 的 `costBreakdown` / `recommendations` 都 optional；用 conditional spread 显式跳过 undefined 字段，避免 `costBreakdown: undefined` 在 type-narrowing 时让 report.ts 的 `if (opts.costBreakdown)` 判 truthy 失败（虽然 undefined 也是 falsy，但显式更稳）。`recommendations.length > 0` 才传也省一次 ''-return 路径
- **NEVER-throw 守恒：recommend() 调用包 try/catch**：recommend.ts 内部已双层 try/catch（per-rule + per-bucket），但 caller 仍包一层兜底 — 防止 import-time 评估失败 / 不可预期的 type drift。任意异常 → 空 `recommendations[]`，章节静默跳过，与"7 flat section 不破"契约一致
