## Learnings (Task 2.5, 2026-05-07)

- **parseCorrelationId 严格 3 段判定**：`split(':')` length !== 3 或任一段空字符串 → 整体回 `{}` 而不是部分匹配。部分匹配会让 `parsed.sid` 出现而 `parsed.task` 缺，导致 spec 维度桶命中但 task 维度走 unknown，跨 level 总和不一致（双计风险）。Decision 11 双分桶能成立的前提就是 correlationId 全段一致或全段缺。
- **specPhaseMap 缺 sid 走 unknown，不是漏 phase**：`specPhaseMap[parsed.sid]` 即使 sid 存在也可能查不到 phase（如 .curdx-state.json 文件刚被删）。统一走 `unknown` 桶比"sid 命中但 phase undefined"分两类好——前者透明可观测（report 有 unknown 行），后者会产生 undefined key 字面量混入桶。
- **modelMix tokens 不含 cache_***：design §Components 没明说 cache 是否进 mix.tokens；选择 `inputTokens + outputTokens` 而排除 cache_read/5m/1h，因为 R6 tokenizer cohort 比较的是 generation tokens（input prompt + output completion），cache write/read 是 billing 副产物，混进会让不同 cache 命中率的 model 被不公平归类
- **boundary round-then-sum vs sum-then-round**：computeCost 单行已 4 位 round；buckets 累加时再 round 一次（`Math.round(b.totalUSD * 10000) / 10000`），双 round 累计漂移上界 N × 0.00005，对 N=10K 行 ≈ 0.5 USD 仍远低于 ±0.001 AC3 但稳妥；render 层（Phase 4 report.ts）可继续 `.toFixed(4)` 不再 round
- **parent + trailer 同 correlationId 合桶 = R3 task 维度核心**：smoke 验证 `specA:1.1:1` 桶包含 1 parent (model='claude-opus-4-7') + 1 trailer (model='unknown') → rowCount=2 / trailerCount=1 / durationMs=9450 (从 trailer 继承)。Decision 11 落地证。
- **bucket sort desc by totalUSD**：R7_topN flag (`--top 5`) 在 Task 2.7 接线时直接 `buckets.slice(0, top)` 即可，不在 render 层再排序。AggregateBucket 自带 sort 契约。

## Learnings (Task 2.6, 2026-05-07)

- **state-file 无 sessionId 字段**：实地核验 `specs/spec-decision-event-logging/.curdx-state.json` 等三个样本 state 文件，shape 为 `{source, name, basePath, phase, taskIndex, taskIteration, globalIteration, ...}`，无 `sessionId` 也无 `transcriptPath`。Task 2.6 brief 已预见到此情况："if state.sessionId is missing, use spec name as fallback key"。最终选择直接用 `name` 作为 key — 简单、决定性、零额外读盘

## Learnings (Task 2.7, 2026-05-07)

- **flag 选择三态 — anyByFlag gate**：四个 flag 互动语义用一行短路收口：`const anyByFlag = bySpec || byPhase || byTask; const wantX = anyByFlag ? Xflag : true;` 既覆盖"任一 true → 仅那些维度"也覆盖"全 false + costSummary → 全开 R1+R2+R3+R7"，比 if/else 链 + early return 少 1 嵌套层级

- **AnalyzeOptions 同步扩 4 字段**：flows/analyze.ts 的 `AnalyzeOptions` 类型与 src/analyze/types.ts 的 `Options` 是两套但都需要扩 — `Options` 在 Task 1.1 已扩，本任务补上 `AnalyzeOptions` 的 4 个新字段保持类型 surface 对齐
- **citty kebab→camel 双形式贯穿**：4 个新 flag 全走"kebab args key + camel runtime opts"双形式（`'by-spec'` → `bySpec`），与 `cost-summary` / `include-prompts` 同款。citty meta 用 kebab，runtime opts 用 camel 是已建立 idiom
