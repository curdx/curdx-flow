# Execution Brief

Use the execution brief when a route needs more than a single direct edit.
It is generated by:

```bash
curdx-flow route --compile --goal "<goal>"
```

The brief turns router facts into a bounded execution contract.
It is read-only by default. Use `--record` only for real execution flows that
should append a compact `route-compiled` event to `.curdx/brain.jsonl`; do not
use `--record` during prompt optimization.

## Fields

- `route`: workflow decision from smart-route.
- `stack`: primary stack profile.
- `context`: maximum reference file budget, read-first hints, and avoid list.
- `execution`: primary curdx-flow skill, agent plan, isolation boundary, and
  task shape.
- `qualityGates`: phase-specific docs, TDD, verification, security, browser, or
  release gates.
- `completionContract`: evidence required before claiming completion.
- `escalationRules`: when to ask, switch to debugging, add directories, or run
  official release validation.
- `brain`: recent project-local learning from `.curdx/brain.jsonl`.

## Rules

- The brief is a contract, not decoration. Do not claim completion until the
  completion contract is satisfied.
- Do not exceed `context.maxReferenceFiles` unless a blocker proves the budget
  is too small.
- For `direct-change`, keep execution local and small.
- For `full-spec`, `epic-split`, critical release, security, or plugin work,
  use the listed review agents and isolation boundary.
- Treat `.curdx/brain.jsonl` as advisory memory only. Repository files and fresh
  verification evidence always win.
- Never store secrets, full prompts, source contents, or user private data in
  brain events.
